# ResearchOS V0.2 Roadmap

Status: proposed after open-source capability review  
Snapshot date: 2026-10-06

## V0.2 objective

Move ResearchOS from a strong **research reasoning framework** into a usable **research execution framework** without weakening evidence discipline.

V0.1 answers:

> What should we research, why, how should we test it, what do the results justify, and how should the paper be audited?

V0.2 should additionally answer:

> How do we ingest real sources, execute real experiments, analyze them correctly, preserve provenance, resume long work, and manage submission rounds?

## P0 — Required for practical end-to-end use

### 1. Source Ingestor / Paper Digester

New module:
`source-ingestor`

Responsibilities:
- accept PDF / DOI / arXiv / local paper / bibliography entries,
- verify bibliographic identity,
- extract structured paper notes,
- preserve page/figure/table pointers,
- deduplicate versions,
- create one atomic literature-ledger entry,
- expose source evidence to Literature Mapper and Paper Auditor.

Design inspirations:
- Academic Research Skills `digest-paper`,
- Academic Research Agent tool-assisted PDF ingestion,
- AI4S source-grounding rules.

Hard rule:
no partial "citation exists" state where bibliography metadata is saved but scientific evidence was never inspected.

### 2. Experiment Executor

New module:
`experiment-executor`

Responsibilities:
- consume a READY experiment contract,
- materialize code/config only after authorization,
- run smoke test separately from scientific experiment,
- record environment, hardware, versions, seeds, commands,
- persist raw outputs,
- never promote results to claims,
- hand outputs to Result Auditor.

Modes:
- local,
- remote/cloud,
- user-run package,
- dry-run/simulation clearly marked as non-evidence.

Hard rule:
simulated/illustrative values never become measured evidence.

### 3. Statistical Analysis Adapter

New module:
`statistics-adapter`

Responsibilities:
- define estimand and experimental unit,
- choose appropriate analysis,
- check assumptions,
- calculate effect size and uncertainty,
- power/sample-size planning when applicable,
- distinguish exploratory and confirmatory analysis,
- pass structured statistical evidence to Result Auditor.

Preferred strategy:
integrate or hand off to mature statistics skills rather than recreating a complete statistical library.

### 4. Runtime Checkpoint and Resume Contract

Add:
- `run_state.yaml`
- step checkpoints,
- artifact completion flags,
- last verified gate,
- recovery instructions,
- branch/protocol version references.

Goal:
after context loss, ResearchOS should reconstruct:
- current scientific contract,
- current gate,
- last accepted evidence,
- pending decision,
- prohibited work.

### 5. Validation / Lint Layer

Add automated checks for:
- YAML schema validity,
- unique IDs,
- dangling claim/evidence IDs,
- invalid epistemic transitions,
- unsupported `SUPPORTED` claims,
- manuscript claims absent from Claim Ledger,
- experiment READY state missing required fields,
- stale references after protocol version changes.

Suggested commands:
- `researchos validate`
- `researchos trace C001`
- `researchos gate-status`

## P1 — High value after P0

### 6. Math / Claim Formalizer

New module:
`claim-formalizer`

Responsibilities:
- define minimum mathematical object needed to make a claim falsifiable,
- variables,
- objective,
- assumptions,
- units,
- metric definition,
- causal/identification target where relevant.

Do not add equations merely for visual rigor.

### 7. Editable Figure Pipeline

New modules:
- `figure-planner`
- `figure-builder`
- `figure-auditor`

Canonical artifacts:
- `figure_spec.yaml`
- `figure_manifest.yaml`

Core rule:
- data figures are structured-first and regenerated from real data/artifacts;
- scientific diagrams are semantic-spec-first;
- image-generation models may assist visual ideation but cannot define scientific values, modules, or relationships.

Builder MVP:
- line, bar, scatter, heatmap,
- flowchart and architecture diagram,
- SVG / PDF / PNG preview,
- PPTX when practical,
- stable object IDs and semantic grouping,
- source/claim provenance.

Auditor:
- number consistency,
- axis/legend/unit checks,
- source-data trace,
- editable text/object checks,
- SVG path/group sanity,
- manuscript-text consistency,
- editability grading E0-E4.

Detailed design:
`docs/FIGURE_PIPELINE_DESIGN.md`

V0.3 extension:
`image-to-editable-bridge` for provider-agnostic GPT-Image / Google image-model / other image draft generation followed by semantic reconstruction into SVG/PPTX/Canvas-style editable objects. Blind bitmap tracing is not considered sufficient editability.

### 8. Submission Manager

New module:
`submission-manager`

Lifecycle:
- submission preparation,
- immutable submitted snapshot,
- decision ingestion,
- reviewer concern map,
- rebuttal,
- revision promises,
- revision trace,
- re-submission,
- camera-ready freeze.

Hard rule:
never edit frozen submitted archives.

### 9. Venue Profile

New module or data pack:
`venue-profile`

Store time-sensitive venue requirements:
- length,
- anonymity,
- supplementary policy,
- artifact/code/data requirements,
- AI disclosure,
- formatting,
- rebuttal constraints.

Requirements must be fetched from current official sources when used.

## P2 — Expansion

### 10. Systematic Review / Meta-analysis Mode

Add when formal evidence synthesis is requested:
- protocol,
- databases,
- search strings,
- duplicate screening,
- inclusion/exclusion,
- PRISMA-style flow,
- risk of bias,
- effect-size synthesis,
- publication-bias considerations.

### 11. Domain Adapters

Potential adapters:
- AI/ML,
- systems,
- software engineering,
- remote sensing/geospatial,
- experimental agriculture/phenotyping,
- HCI/user study.

Adapters should add:
- checklists,
- standard metrics,
- common threats,
- field-specific reproducibility requirements.

They should not replace ResearchOS core logic.

### 12. Integrity Forensics

Optional advanced extension:
- image duplication/transformation checks,
- arithmetic re-derivation,
- source-data/table consistency,
- suspicious numerical patterns,
- correction/retraction tracking.

Keep evidence grading separate from misconduct verdicts.

## Orchestrator evolution

V0.2 root routing should become:

```text
DISCOVERY
Research Radar
  -> Scientific Brainstorming
  -> Idea Auditor

GROUNDING
Research Intake
  -> Source Ingestor
  -> Literature Mapper
  -> Claim Formalizer / Hypothesis Builder

EXECUTION
Experiment Designer
  -> Statistics Adapter
  -> Experiment Executor
  -> Result Auditor

COMMUNICATION
Figure Planner
  -> Figure Builder
  -> Figure Auditor
  -> Paper Builder
  -> Paper Auditor

SUBMISSION
Venue Profile
  -> Submission Manager
  -> Rebuttal / Revision
  -> Camera-ready freeze
```

## What not to build in V0.2

Avoid:
- 100+ domain-specific API skills inside ResearchOS,
- fully autonomous unsupervised story pivots,
- automatic "best venue" submission without user approval,
- automatic paper claims from raw run outputs,
- simulated experimental evidence presented as real,
- decorative agent-role hierarchies without decision value.

## Acceptance criteria for V0.2

V0.2 is ready when a new research direction can complete this path:

1. current topic discovery,
2. candidate idea generation,
3. literature grounding from inspected real papers,
4. hypothesis/formal claim,
5. execution-ready experiment contract,
6. reproducible experiment run or user-run package,
7. statistical/result audit,
8. claim promotion,
9. evidence-bound manuscript,
10. paper audit,
11. frozen submission snapshot,
12. reviewer concern/revision loop,

while preserving a traceable chain from every central manuscript claim back to its source or experiment artifact.
